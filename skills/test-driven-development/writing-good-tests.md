# 写好测试

**何时加载此参考：** 编写或修改测试、添加 mock、或为测试添加清理/辅助方法时。

## 两条原则

**① 每个测试要能说出它捕获哪种破坏。② 每个测试要跑真实的东西。**

严格 TDD 自然产出这两条：先写、看着它失败，就已证明它能失败；真实依赖确实慢或是外部时，才配得上一个 mock。

## 原则一：说出它捕获哪种破坏

写测试体之前先回答：**哪处生产改动会让它失败——那是 bug，还是个决定？** 只因常量值、消息措辞、私有结构这类刻意决定才失败的测试是「改动探测器」：重构就红，真 bug 睡过头。期望值必须独立推导——由被测代码或其 helper 算出的期望值（镜像断言）恒真。

```typescript
const expected = buildSearchQuery({ tag: 'urgent' });              // ❌ 同一个 builder 算两侧
expect(buildSearchQuery({ tag: 'urgent' })).toBe(expected);        //    恒真，什么都没测
expect(buildSearchQuery({ tag: 'urgent' })).toBe('tag:"urgent"');  // ✅ 手写字面量
```

### 写前自检一（写测试体之前）

```
问："哪处生产改动会让它失败？"
  说不出、或只有刻意决定能失败  → 重设计到可观察行为
  只会因"源文本变了"而失败       → 改成跑产物、断言其副作用或退出码
  期望值由被测代码/其 helper 算出 → 换成手写常量或手工核对的 fixture
```

## 原则二：跑真实的东西

**mock 不配拥有断言。** 断言 mock 存在，mock 在就过、不在就挂——对组件什么也没说。

```typescript
expect(screen.getByTestId('sidebar-mock')).toBeInTheDocument();  // ❌ 测的是 mock 存在
expect(screen.getByRole('navigation')).toBeInTheDocument();      // ✅ 测真实组件
```

### 写前自检二（加 mock 或测试辅助方法之前）

```
1. 先列出真实方法的全部副作用；测试依赖的那部分保持真实，只 mock 慢的/外部的那一层。
2. mock 响应镜像完整的真实结构——缺字段会在下游静默失败。
3. 只被测试调用的方法（如 destroy()/cleanup()）放测试工具类，不进生产类——判据：它是否只被测试调用？这个类是否拥有该资源的生命周期？
4. mock 设置超过测试逻辑一半 → 改成跑真实组件的集成测试。
```

## 收尾变异检查

完成前心智变异生产代码——改错常量、走错分支、丢掉副作用、返回默认值、丢掉校验（零值/空/nil/未授权/畸形输入）——每一类现实变异，至少要有一个测试挂掉。挂不掉 → 该行为无保护，或测试是同义反复。

## 三条反模式

| 反模式 | 为什么错 | 修复 |
|--------|---------|------|
| 断言 mock 存在 | 测的是 mock，不是组件 | 测真实组件，或取消 mock |
| 给生产类加测试专用方法 | 污染生产类，违反 YAGNI | 移到测试工具类 |
| 不理解副作用就 mock | mock 吞掉下游依赖的副作用（如吞掉配置写入，而重复检测要读它） | 先列出副作用，只在正确层级 mock |
