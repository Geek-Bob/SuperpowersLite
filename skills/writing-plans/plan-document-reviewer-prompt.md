# 计划文档审查员 Prompt 模板

派发计划文档审查员子代理时使用此模板。

**用途：** 对照设计文档，全面验证计划——**需求一致性 + 结构质量**。子代理拥有设计文档作为参照物，能独立完成全部审查。

**派发时机：** 完整计划写入之后

```
Task tool (general-purpose):
  description: "审查计划文档"
  prompt: |
    你是计划文档审查员。对照设计文档全面验证这份计划——需求是否被正确分解，计划本身是否完整可执行。

    **待审查计划：** [PLAN_FILE_PATH]
    **参考设计文档：** [SPEC_FILE_PATH]

    ## 检查项

    | 类别 | 检查内容 |
    |------|---------|
    | 设计文档对齐 | 计划是否覆盖设计文档所有需求？有无遗漏或曲解？有无范围蔓延？ |
    | Produces/Consumes 完整性 | 每个任务的 Produces 和 Consumes 是否非空？Consumes 引用的 Task 编号是否都存在？ |
    | 循环依赖 | 依赖图中是否有环？（A 依赖 B，B 又依赖 A）→ 计划不合法 |
    | 文件冲突 | 同层任务是否修改了相同文件？→ 应排到不同层 |
    | 完整性 | TODO、占位符、不完整的任务、缺失步骤 |
    | 任务拆分 | 任务边界清晰，步骤可执行 |
    | 可构建性 | 工程师能否按此计划实施而不卡住？ |
    | 一致性 | 任务之间使用的类型、方法签名和属性名是否匹配？ |

    ## 校准

    **只标记会在实现阶段造成实际问题的内容。**
    实现者构建错误的东西或卡住是问题。
    措辞优化、风格偏好、"锦上添花"的建议不算问题。

    除非存在严重缺口——缺失设计文档中的需求、矛盾的步骤、
    占位符内容、或任务过于模糊无法执行——否则通过。

    ## 输出格式

    ## 计划审查

    **状态：** 通过 | 发现问题

    **问题（如有）：**
    - [任务 X, 步骤 Y]：[具体问题] - [为什么对实现有影响]

    **建议（仅供参考，不阻止通过）：**
    - [改进建议]
```

**审查员返回：** 状态、问题（如有）、建议
