# 子代理驱动开发

派子代理执行计划。每个任务：实现 → 合规审查 → 质量审查。通过后标记完成。

## 前置条件

计划已被用户确认。未确认？停止。回去请用户审阅。

## 执行

```
读取计划 → 提取所有任务 → TodoWrite → 逐个执行
```

不间断执行所有任务。只在以下情况停下：BLOCKED 无法解决、真正阻塞的歧义、全部完成。

## Per Task 流程

```
派实现者 → TDD/测试/提交/自审
  → 派 task-reviewer → 合规？
    → ❌ SendMessage 原实现者修复 → 重新审查
    → ✅ 派 code-quality-reviewer → 通过？
      → ❌ SendMessage 原实现者修复 → 重新审查
      → ✅ TodoWrite 完成 + Edit 计划 checkbox [-]
```

## 计划文件追踪

TodoWrite 标记完成后，立即 Edit 计划文件：`- [ ]` → `- [x]`。进度持久化。

## 两阶段审查

控制器只协调，不审查，不修代码。

### 第一阶段：任务合规

1. 派 task-reviewer 子代理，模板 `./task-reviewer-prompt.md`
2. 提供：完整任务内容 + 设计文档索引（路径 + 章节锚点，审查员按需读取）
3. ❌ → SendMessage 原实现者修复 → 派新 task-reviewer 重新审查
4. ✅ → 进入第二阶段

### 第二阶段：代码质量

1. 派 code-quality-reviewer 子代理，模板 `./code-quality-reviewer-prompt.md`
2. ❌ → SendMessage 原实现者修复 → 派新 code-quality-reviewer 重新审查
3. ✅ → 标记完成

### 派发铁律

| 角色 | 怎么派 |
|------|--------|
| 实现者 | 新子代理 |
| 实现者修复 | **SendMessage** 同一个（保留上下文） |
| 审查员 | **每次新子代理**（全新视角，无偏见） |
| 控制器 | 只读报告、只决定下一步 |

### 绝对禁止

- 控制器自己读代码、自己审查
- 控制器自己修代码
- 跳过任一审查
- 审查有未解决问题时进入下一任务
- 任务合规未通过就开始代码质量审查
- 派新实现者修复（必须 SendMessage 原实现者）

## 处理实现者状态

| 状态 | 动作 |
|------|------|
| DONE | 进入任务合规审查 |
| DONE_WITH_CONCERNS | 读顾虑。正确性/范围问题 → 修复后再审查。观察性意见 → 记录，继续审查 |
| NEEDS_CONTEXT | 补充上下文，重新派发 |
| BLOCKED | 上下文不足 → 补充后重派。需更强推理 → 升级模型。任务太大 → 拆分。计划问题 → 升级给用户 |

别忽略升级。别不改变就重试。卡住了就必须改变什么。

## 模型选择

机械任务（1-2 文件、清晰规格）→ 便宜模型。集成任务（多文件、跨模块）→ 标准模型。审查/架构 → 最强模型。

## Prompt 模板

- `./implementer-prompt.md` — 实现者
- `./task-reviewer-prompt.md` — 任务合规审查员
- `./code-quality-reviewer-prompt.md` — 代码质量审查员

## 红线

- 别在 main/master 上执行
- 别跳过审查
- 别带未修复问题继续
- 别并行派多个实现者（会冲突）
- 别让子代理读计划文件（你提供完整文本）
- 别忽略子代理提问
- 别接受"差不多"的任务合规
- 别用自审替代实际审查
- 控制器不审查、不修代码

子代理提问 → 清晰完整回答。审查发现问题 → 修复 → 重新审查 → 循环直到通过。任务失败 → 派修复子代理，别手动修。
