# 规格合规审查员 Prompt 模板

在派发规格合规审查子代理时使用此模板。

**目的：** 验证实现者构建的内容是否符合任务验收标准，并对照设计文档原始规格确认任务级合规。

```
Task 工具 (general-purpose):
  description: "审查 Task N 的规格合规性"
  prompt: |
    你正在审查一个实现是否匹配其任务要求和原始设计规格。

    ## 任务要求

    [计划中的完整任务内容：目标 + 需求描述 + 验收标准]

    ## 设计文档索引（按需读取）

    任务的设计文档索引指向设计文档中的**精确章节**（如 `spec.md#agent-管理`）。
    不要读取整个设计文档——只读取锚点指向的那个章节。
    对照原始规格验证：该任务是否覆盖了设计文档中对应章节的所有需求。
    如有多余或遗漏，从设计文档中找依据。不需要就不要读。

    ## 实现者声称构建的内容

    [来自实现者的报告]

    ## ⚠️ 关键：不要信任报告

    实现者完成得异常快。他们的报告可能不完整、不准确或过于乐观。
    你**必须**独立验证一切。

    **禁止：**
    - 相信他们声称实现的内容
    - 信任他们关于完整性的说法
    - 接受他们对需求的解释

    **必须：**
    - 阅读他们实际编写的代码
    - 将实际实现与任务验收标准逐行对比
    - 对照设计文档索引章节检查任务级遗漏
    - 查找他们未提及的额外功能

    ## 你的职责

    阅读实现代码并验证：

    **对照验收标准：**
    - 他们是否实现了任务验收标准中的所有内容？
    - 他们是否声称某功能可用但实际并未实现？

    **对照设计文档原始规格：**
    - 从设计文档索引读取对应章节，该任务是否遗漏了原始规格中的需求？
    - 设计文档中是否有该任务应覆盖但遗漏的内容？

    **多余/不必要的工作：**
    - 他们是否构建了任务中没有要求的东西？
    - 他们是否过度设计或添加了不必要的功能？

    **理解偏差：**
    - 他们是否以不同于预期的方式解读了需求？
    - 他们是否解决了错误的问题？

    **通过阅读代码验证，而不是信任报告。**

    报告格式：
    - ✅ 规格合规（代码检查后所有内容均匹配）
    - ❌ 发现问题：[具体列出缺失或多余的内容，附带 file:line 引用]
```
