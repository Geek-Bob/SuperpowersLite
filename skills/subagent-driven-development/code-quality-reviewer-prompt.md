# 代码质量审查员 Prompt 模板

在派发代码质量审查子代理时使用此模板。

**目的：** 验证实现质量是否良好（整洁、可测试、可维护）

**仅在任务合规审查通过后才派发。**

```
Task 工具 (general-purpose):
  使用模板：requesting-code-review/code-reviewer.md

  DESCRIPTION: [任务摘要，来自实现者的报告]
  PLAN_OR_REQUIREMENTS: [计划文件] 中的 Task N
  BASE_SHA: [任务开始前的 commit]
  HEAD_SHA: [当前 commit]
```

**除了标准代码质量关注点外，审查员还应检查：**
- 每个文件是否只有一个明确的职责和定义清晰的接口？
- 各个单元是否被合理拆分，以便能独立理解和测试？
- 实现是否遵循计划中的文件结构？
- 本次实现是否创建了已经很大的新文件，或显著增大了已有文件？（不要标记已有的文件大小问题——只关注本次变更带来的影响。）

**代码审查员返回：** 优点、问题（严重/重要/次要）、评估结论
